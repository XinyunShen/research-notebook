# Phase 2 — 主题热度指数 + 主题贝塔（机制B验证）

对应 `../design_doc.md` 3.2节 + 第8节"验证机制B"。目标：把"AI产业链传导"从
"证明因果"（机制A，很难）换成"证明共振强度"（机制B，用回归可测），
第一次用真实数据跑一遍这个思路。

## 已实现

- **主题热度指数**（`src/theme_index.py`）：三路免费信号的等权合成
  1. L1核心股（NVDA/AMD/AVGO/TSM）动量——有两个版本，见下方"行业共振修复"
  2. 第二路信号有两个版本，二选一，见下方"circularity修复"：
     - 旧版（有circularity问题）：SOXX/SMH 近期成交量相对自身历史的偏离
       （design_doc.md 5.7节 Tier 4 的免费代理指标，**不是真实ETF净申购/
       赎回资金流**，是已知简化）
     - 新版（修复circularity，`src/google_trends.py`）：Google Trends
       搜索热度。关键词迭代过两次（design_doc.md 12节问题16）：从通用词
       ("semiconductor stocks"/"AI stocks") 换成3个叙事专属词，又扩充到
       7个覆盖L2设备/L3散热/L4电力全部层级（`semiconductor equipment` /
       `HBM memory` / `chip packaging` / `data center cooling` /
       `diamond heat spreader` / `data center power` /
       `AI power demand`），当前用的就是这7个。和任何被测股票都不重叠
  3. 新闻热度趋势（Tier 3, Finnhub，`src/news_finnhub.py`）——`pipeline.py`
     已接好自动调用：设置了 `FINNHUB_API_KEY` 环境变量就会自动拉取**L1
     核心股**（NVDA/AMD/AVGO/TSM）的每日新闻提及量趋势，加入指数；没设置
     就自动跳过，退化成只用前两路信号。**只拉L1、不拉下游候选股**是有意
     设计：新闻信号如果拉的是被测股票自己的新闻量，会和下面circularity
     问题犯同一种错误。**已用真实API Key实测，结果是负面发现**：Finnhub
     免费层`company-news`接口给不了2016-2026这段历史所需的新闻深度（实测
     对NVDA查2020年1月返回0条，查10年区间也只返回最近249条），导致这一路
     信号在滚动z-score窗口里几乎全是NaN，`theme_heat_index`用`skipna`平均
     时把它悄悄忽略掉了——**IC/IC_IR数字和不设Key时完全一样**，不是"新闻
     没用"，是"免费层没有这段历史"。管道现在会显式打印WARNING而不是静默
     忽略，见下方"新闻信号实测结果"。
  三路信号标准化都用**滚动**（而不是全样本）z-score，避免用未来数据校准
  今天的标准分——这也是一种容易被忽略的前视偏差来源。
- **科技板块基准**（`src/benchmark.py`）：复用 Phase 1 科技基础池（排除
  AI产业链池本身，避免自我印证），等权合成一条"泛科技板块"日收益率，
  用来把 L1核心股和下游候选股的收益都换算成"超额收益"（原始收益-基准
  收益），剔除"这些公司本来就都是科技/半导体股，日常同涨同跌"这层
  普通行业共振。
- **主题贝塔**（`src/thematic_beta.py`）：L2-L4 每只候选股，滚动126日窗口
  回归其（超额）日收益率对主题热度指数日度变化的暴露度（beta），用滚动
  协方差/方差算，等价于滚动OLS斜率但快很多。
- **验证**（`src/validate.py`，同 Phase 1 一样用 Alphalens）：把"主题贝塔"
  当成一个因子，检验它本身对下游股票未来收益有没有预测力。

## 运行方法

```bash
cd phase2
source ../phase1/.venv/bin/activate   # 复用 Phase 1 的虚拟环境，无需重装依赖
python -m src.pipeline

# 可选：想接入新闻热度这一路信号
export FINNHUB_API_KEY=你的免费key   # https://finnhub.io/register 免费注册
python -m src.pipeline
```

每次运行会**同时**跑 raw（未剔除行业共振的旧版本）、excess（已剔除行业共振、
ETF成交量版）、trends（已剔除行业共振 + Google Trends替换ETF，修复
circularity）三条，方便直接对比，输出文件用 `_raw` / `_excess` / `_trends`
后缀区分。Google Trends走非官方pytrends库，限流经常发生，拉取失败时会
自动跳过trends这条对比线，只跑raw/excess两条（不会让整个管道崩掉）。

## 两个方法论缺陷修复对比 + 关键词精修（19只下游候选股，2016年至今）

| | raw（都没修） | excess（剔除行业共振） | trends（通用关键词） | trends（叙事专属关键词） |
|---|---|---|---|---|
| 63日 Rank IC 均值 | 0.0891 | 0.0884~0.0902 | 0.0198 | **0.0828** |
| 63日 IC_IR | 0.2326 | 0.2565~0.2633 | 0.0545 | **0.2184** |

（excess列两次跑之间数字有微小差异是Google Trends周频数据每次拉取的
边界日期不完全一致导致的正常波动，不是bug）

**第一步（剔除行业共振，raw→excess）**：IC没有下降，反而略微提高。
说明"IC大部分是行业共振假象"这个担心没有发生。

**第二步（修circularity，excess→trends，通用关键词）**：用Google Trends
搜索热度（"semiconductor stocks"/"AI stocks"）替换SOXX/SMH成交量后，
**63日IC从0.09暴跌到0.0198**，分层收益也不再单调。当时的解读是"之前的
IC相当一部分是circularity在自我印证"。

**第三步（换叙事专属关键词，design_doc.md 12节问题16）——这一步再次
扭转了结论**：把关键词从通用词换成直接对应3.2.1节产业链叙事的词
（"AI data center"/"data center cooling"/"data center power"，分别
呼应L2设备/L3液冷/L4电力这几层实际在讲的故事），**63日IC从0.0198回升
到0.0828，IC_IR从0.0545回升到0.2184**——几乎追平了还带着circularity
问题的excess版本，分层单调性也明显改善。**这是基于叙事逻辑一次性选出
来的关键词，不是试了很多组合挑IC最好看的那组**（那样做就是过拟合/
数据窥探）。

**结果解读**：第二步的"信号基本消失"看起来相当一部分是**关键词选得
太笼统导致的噪音**，不是circularity修完后机制B真的没有预测力。
"semiconductor stocks"会被存储器涨价、PC/手机需求这些和AI叙事无关的
因素带偏；"AI stocks"和L1核心股动量高度重叠，信息增量有限。换成贴近
实际叙事的关键词后，一个真正干净、不重叠的信号重新显现出接近excess
版本的预测力，说明机制B**很可能是真实存在的**。

**但必须诚实指出一个隐忧**：仅仅换一次关键词就让IC涨了4倍多，说明
**信号对关键词选择本身高度敏感**——这本身是需要警惕的信号，不是纯粹的
好消息。

**第四步（第二次扩充关键词，不是因为结果不好看，是因为覆盖面本来就不
完整）**：3.2.1节产业链比原来3个关键词覆盖的窄很多——L2（设备/材料层）
完全没有对应词，L3只覆盖了"液冷"没覆盖同样真实的"人造钻石散热"这条
2026年的新兴趋势（用WebSearch核实过：AI芯片功耗超2000W、热流密度超
1000W/cm²逼近传统铜散热极限，CVD人造钻石导热率是铜的5倍，2026年已
进入8寸晶圆量产阶段，市场规模从2亿美元冲向4.3亿美元(2035)，是真实
产业趋势）。关键词从3个扩到7个：`semiconductor equipment` / `HBM
memory` / `chip packaging`（L2）、`data center cooling` / `diamond
heat spreader`（L3）、`data center power` / `AI power demand`（L4）。

**结果**：63日IC = **0.0883**，IC_IR = **0.2280**——和3关键词版本的
0.0828/0.2184几乎一样，也几乎完全追平excess版本（0.0884/0.2565），
分层收益变成了干净的阶梯状单调递增。**这次的意义不是"数字又变好了"，
而是两组独立推理出的关键词（3个窄的、7个宽的）分别给出0.083和0.088，
落在同一个区间**——比只有一次关键词改动更让人放心，不太像是巧合。

**当前最诚实的结论**：机制B信号存在的证据比上一轮更强了，"对关键词
选择的敏感度"这个隐忧因为第二组关键词而有所缓解（但没有消除——两次
测试仍然在同一批2016-2026历史数据上跑的，不构成真正的样本外检验）。
**关键词调整到此为止**，不再继续增删关键词去追更好看的数字。

## AI叙事诞生前/后分段检验

一个尖锐但很合理的质疑：AI作为能推动股价的叙事，公认从2022年11月
ChatGPT发布之后才真正成气候，2016-2022年根本没有这回事（比如L4的
Constellation Energy被当成"AI电力股"是2023-2024年跟云厂商签购电协议
之后才有的事）。用整个2016-2026十年的均值测"AI叙事共振"，会不会被
"叙事根本不存在"的那几年严重稀释或者污染？

`pipeline.py`加了分段检验（`SPLIT_DATE=2023-01-01`），把raw/excess/
trends三个版本各自拆成"叙事前"（2016-2022）和"叙事后"（2023-2026）
分别算IC：

| | 叙事前63日IC | 叙事后63日IC | 叙事前IC_IR | 叙事后IC_IR |
|---|---|---|---|---|
| raw | 0.0640 | 0.1384 | 0.17 | 0.37 |
| excess | 0.0640 | 0.1364 | 0.18 | 0.42 |
| trends | 0.0729 | 0.1190 | 0.18 | 0.35 |

**结果解读**：
1. 三个版本一致显示"叙事后"的IC和IC_IR大约是"叙事前"的2倍——信号
   确实在ChatGPT之后显著更强，直接印证了这个质疑的方向是对的。
2. 但"叙事前"也不是纯噪音（IC还有0.06-0.07）——半导体/科技供应链
   本身在AI概念破圈前可能就有类似的行业共振效应，"AI叙事"看起来是把
   一个本来就存在的效应放大了，不是从0凭空造出来的。
3. **三个版本呈现同样的翻倍模式这一点很关键**——如果只有trends版本
   显示这个模式，会怀疑是Google Trends关键词语义漂移（"data center
   cooling"在2018年搜索大概率和AI无关）导致的假象；三个版本一致，
   说明这是更底层、更真实的现象。

**这不是真正意义上的样本外检验**（同一批数据、同一套方法论，只是按
时间切开看），但直接回应了"用10年数据测一个3年新叙事是否合理"这个
具体质疑，结果是合理的。design_doc.md 12节问题17把"要不要做更严格的
独立样本外检验"列为待决定的问题。

## 新闻信号实测结果（2026-07-21，真实Finnhub API Key）

拉取到L1核心股的新闻数据（AMD 7条、AVGO 12条、NVDA 2条、TSM 46条，均
集中在最近1-7周），但接入`theme_heat_index`后**IC/IC_IR和不设Key时完全
一样**（63日IC 0.0891/0.0902，raw/excess两版都不变），因为：

- Finnhub免费层`company-news`没有深历史：实测查NVDA 2020年1月整月返回
  **0条**，查2016-2026整个10年区间也只返回**249条**（且是最近的249条，
  不是按请求区间均匀分布的历史数据）。
- `news_heat_component`的滚动z-score需要至少63天非空数据才输出数值
  （`ZSCORE_WINDOW=252, min_periods=63`），而实际非空天数是0——新闻数据
  存在，但集中在最近1-7周，不够填满63天的最短窗口要求。
- 结果：`news_heat_z`列全是NaN，`theme_heat_index`用`skipna=True`平均时
  把这一路自动跳过，等于这次回测里新闻信号没有产生任何影响。

**这不是bug，是数据源限制**，管道现在会显式打印WARNING提示这种情况
（不再是静默无效果）。新闻信号的代码基础设施是通的，但要在2016-2026这
段历史里真正验证它，需要升级付费新闻源、换有历史深度的数据源，或者把
新闻信号从"历史回测因子"改成"只用于往前滚动的实时/paper trading信号"
——这三个方向还没定（design_doc.md 12节问题14）。

## 已知限制 / 下一步

1. **样本量天然小**（19只下游股票）——design_doc.md 第8节"第零步"已经说明
   这是产业链传导策略的先天短板，不是这里能解决的。
2. **circularity 已修复，结果目前是正面的，但没做过样本外检验**——用
   Google Trends替换ETF成交量、并用7个覆盖3.2.1节全部层级的叙事专属
   关键词后，主题贝塔的IC（0.088）几乎追平了还带circularity问题的
   excess版本。**当前最重要的悬而未决问题**：这个结果的两次关键词测试
   都在同一批2016-2026历史数据上跑的，"信号对关键词选择敏感"这个隐忧
   只是缓解、没有消除，还需要独立样本外检验才能真正确认稳不稳
   （design_doc.md 12节问题17，三个方向都还没定）。
3. **Google Trends本身是已知简化**：这段历史区间pytrends只能拿到周频
   数据（reindex到交易日用前向填充近似）。关键词已经从通用词迭代到
   7个覆盖L2/L3/L4全层级的叙事专属词（见上方"已实现"），不建议再继续
   增删关键词去追更好看的数字（过拟合风险）。pytrends是非官方库，
   限流(429)是常态不是偶发，`google_trends.py`已经做了重试+退避+本地
   缓存。
4. **新闻热度信号接口已打通、已实测，但对2016-2026历史回测没有实际生效**
   ——见上方"新闻信号实测结果"，Finnhub免费层历史深度不够是根因。
5. **ETF成交量异动只是资金流的代理指标**，不是真实净申购/赎回数据，
   design_doc.md 5.7节 Tier 4 已经提示过这个限制（现在已经不是主线信号
   了，只在raw/excess两条对比线里保留，用于展示修复前后的差异）。
